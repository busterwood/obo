# Design notes

- [decimal-research-2026-10-28.md](decimal-research-2026-10-28.md) — database-first research for a lossless decimal type (SQL Server, Oracle, Sybase, PostgreSQL storage formats; 38-digit/24-byte recommendation). Historical research: decimal is released at `0.12`.
- [decimal-language-design.md](decimal-language-design.md) — approved design for language integration of the 24-byte `decimal`, baseline `4a072cf`, after Stage B `0.11`; final literal/type/arithmetic/conversion decisions (bare fractional literals, trap-on-overflow `+ - *`, compile-error `/`, explicit `div` returning `Result`, explicit conversions, display-scale preservation with a DB-style cap, exit-10 trap codes), 24-byte ABI, containers, formatting, database boundary `check`, phased plan and open engineering choices. **Approved 2026-10-31; the minimum scalar tier is released as `0.12`/format 6/ABI 1, merged and promoted on main after rebasing on 0.11 HTML main `34b798b`. The promoted `seed/obo` is the same 0.12 image (643,073 bytes, `d98d6b5f…`), built once by the 0.11 seed `01fa9ed3…`.**
- [stdlib-eza-design-v7.md](stdlib-eza-design-v7.md) — approved v7 design for the CLI stdlib and `eza` core: runtime metadata slots, module APIs, E0/E1/E2 scope, gates and sequencing. Implemented through the E2 core (P3-P6b; see `../FORK.md` and `../cmd/README.md`); the eza 0.23.3 reference pin and probes are recorded in the tests.
- [stdlib-eza-design-v7-review.md](stdlib-eza-design-v7-review.md) — independent APPROVE review of v7.
- [numeric-literals-decision-2026-10-29.md](numeric-literals-decision-2026-10-29.md) — user-approved numeric literal policy: exact decimal by default for fractional and exponent literals, `f`/`F` for binary float; floats at position 11 and decimal at 12; implemented (floats `0.10`, decimal `0.12`).
- [interfaces-design.md](interfaces-design.md) — **Value layer superseded by [interfaces-v3-design.md](interfaces-v3-design.md);** its declaration grammar, `impl` grammar and `.sym` impl lines remain the reference that v3 cites. phase 8 conservative interfaces design: second-class interface values (parameters and locals), frame cells with runtime handle tokens, per-(type, interface) vtables, the `pure` contract for handle-rooted dispatch, symbol format 3, tests/mutants and implementation plan; design only, and its prerequisite is met: methods are merged and the 0.6 seed is promoted (`67799b1`).
- [first-class-interfaces-design.md](first-class-interfaces-design.md) — **superseded by [interfaces-v3-design.md](interfaces-v3-design.md).** The "v2 note": copyable, non-owning interface views (heap cells, provenance, owned-argument rule); not chosen, kept for its review history and as the basis of `^I` phase 2b.
- [owning-interfaces-design.md](owning-interfaces-design.md) — **superseded by [interfaces-v3-design.md](interfaces-v3-design.md).** Alternative value layer to `first-class-interfaces-design.md`: interfaces get the record tiers (`I` owning box, `&I` borrowed, `^I` checked link), a "local" member effect tier, and a fit with the lambdas design (stored behaviour as interfaces, call-scoped behaviour as lambdas); design only, for review.
- [lambdas-design.md](lambdas-design.md) — Stage A non-capturing function literals and structural function types is merged and promoted at `0.9`/format 5/ABI 1. Numeric floats were released before Stage B at `0.10`/format 6/ABI 1. Stage B capture lists were released at `0.11`/format 6/ABI 1, including one-word float snapshots and read-only float carriers; decimal is released at `0.12`/format 6/ABI 1. `^I`, owned/string/interface captures remain deferred. The historical 0.6 baseline header is kept as history.
- [native-c-interop-design.md](native-c-interop-design.md) — **REVISE response, explicit-close adapter checkpoint pending independent rereview** of the one-time generic in-process C interop (`__cinterop`): scalar ABI thunks, maintained ordinary obo wrapper modules, typed sidecar checks, system-toolchain non-PIE linking, conservative effects, provenance gates, a generation-checked C resource registry, and explicit-close libpq Connection/Rows adapters. The repaired scalar prototype and the explicit-close libpq package are in `../experimental/cinterop/`; still **experimental, no stable format, no public portable API and no automatic foreign finalizer**, baseline `0.10`/format 6/ABI 1.
- [interfaces-v3-design.md](interfaces-v3-design.md) — consolidated, implementable interfaces design (owning-first): `I` an owning box, `&I` borrowed with per-local pair slots, `^I` later; the "local" member effect tier with its summary rebuilt from `.sym` markers; parameter modes; `take`/`replace`; the lambda firewall fix (`containsIface` recurses into records); versions `0.8`/format 4/ABI 1 (lambdas shift to `0.9` and `0.10`, format 5); test and mutant inventory; design only, for review. Supersedes `first-class-interfaces-design.md` and `owning-interfaces-design.md` above.
- [interface-handles-design.md](interface-handles-design.md) — phase 2a design for `^I`, a checked handle to an owned interface box, on the released `0.11`/format 6/ABI 1 compiler and Stage B captures: the existing one-word `^T` token naming the box (no runtime/ABI change, but handle-materialization codegen fixes required), `handle` only on owned `I` places (through-handle places refused), `?^I`, liveness/`alive`, copy-only semantics and forbidden equality, dereference-before-arguments dispatch (S4), per-member effect rules with `pure mut` shared sinks, a narrow classifier-only direct-`^I` capture exemption (owned `I`/`&I` deferred), `.sym` compatibility, diagnostics, tests/mutants, and the separate 2b concrete-target pair. Design only, revision 2 for focused re-review; no version reserved.
- [template-literals-design.md](template-literals-design.md) — **approved design decisions 2026-10-31** (revision 3; baseline `c6c4d3f`): compiler-known built-in `sql`/`html` backtick tags over one **template-domain** abstraction, no general user-defined tag protocol in v1; SQL typed bind parameters versus `Sql` fragment composition; explicit `sqlJoin`/`sqlWhere` arrays; splicing consumes fragments and reuse requires `sql.copy`/`html.copy`; ordinary stdlib records with public fields and convention-level trust (not type-enforced); HTML text/quoted-attribute/URL escaping with claimed-safe `Html`/`HtmlAttrs` and rejected script/style/comment/name holes; no cross-domain `SafeString`; implement after Stage B `0.11`, no version reserved. Design only; implementation not authorized.
- [field-visibility-design.md](field-visibility-design.md) — **user decision: record fields are private by default, `pub` per field** (baseline released `34b798b`, `0.11`/format 6/ABI 1): module-level private fields; mixed records; opaque one-word `priv`/`priviface` slots in the `.sym` field list preserving layout without leaking field-list names/types, while exported `pf`/`pfree` summary paths may still name a private field (accepted v1 leak: a private-field change that affects such a summary changes the interface hash, while a field-list-only change may not); external `new T{...}` only when every field is `pub`, otherwise a module constructor; private field types may be private (closure check relaxed) with an interface-carrier bit and per-field clean visited set for the lambda firewall; closed-variant source fields stay public in v1 and migration never adds `pub` to them; methods/interfaces/borrows/moves/handles/C-token interactions, with `buffer::wrap` kept and the C registry as the security boundary; exact diagnostics including the foreign-only private-field-as-method message (public and same-module fields keep the existing field-not-method text); `.sym`/`--check`/hash rules, next-free version coordination with `^I` (no reservation), compiler anchors and the `2,500,000` budget; migration of 103 records, 71 real constructor sites (72 including one `html.obx:18` comment), 147 `pub type` lines, plus 28/22 embedded-Python definitions/sites, 3 regenerable goldens and 92 hand-written `.sym` fixtures; `fs::Dir` remains a public-field v1 exception and `io::Writer` gets `bufferedBytes`; decided private `Html.text` plus `raw` (revision of the template design's public-field sentence, including the `LANGUAGE.md` §8 HTML paragraph and `html.obx` comment). Design only; not implemented.
