# Design notes

- [systems-stdlib-design.md](systems-stdlib-design.md) — design for review on released `51ce9e7` / obo 0.12: general-purpose Linux systems library core (identity, files, directories, metadata, mapping, clocks, random, streams/buffers, network/reactor, processes/signals), HTTP readiness assessment, and the process/reactor concurrency verdict. Core §3–4 and P0/P1a are the approvable slice; P2/P3 are directional; threads and synchronization are not in the core. Docs only, no version reserved.
- [systems-threads-design.md](systems-threads-design.md) — separate P4/P5 design for confined native threads and synchronization on obo 0.12: T2 context-relative globals/identity table as a prerequisite, T1 only as a compute/native restriction, worker-entry ABI without C-to-obo callbacks, hosted TLS/pthread qualification, per-worker arenas, reclamation by joinable supervisor, and P5 byte channels plus AtomicInt/AtomicBool only. SharedBytes/Mutex/Condvar/RwLock/Once and Send/Sync markers are explicitly deferred. Docs only, no version reserved; P4/P5 blocked on T2.
- [decimal-research-2026-10-28.md](decimal-research-2026-10-28.md) — database-first research for a lossless decimal type (SQL Server, Oracle, Sybase, PostgreSQL storage formats; 38-digit/24-byte recommendation). Historical research: decimal is released at `0.12`.
- [decimal-language-design.md](decimal-language-design.md) — approved design for language integration of the 24-byte `decimal`, baseline `4a072cf`, after Stage B `0.11`; final literal/type/arithmetic/conversion decisions (bare fractional literals, trap-on-overflow `+ - *`, compile-error `/`, explicit `div` returning `Result`, explicit conversions, display-scale preservation with a DB-style cap, exit-10 trap codes), 24-byte ABI, containers, formatting, database boundary `check`, phased plan and open engineering choices. **Approved 2026-10-31; the minimum scalar tier is released as `0.12`/format 6/ABI 1, merged and promoted on main after rebasing on 0.11 HTML main `34b798b`. The promoted `seed/obo` is the same 0.12 image (643,073 bytes, `d98d6b5f…`), built once by the 0.11 seed `01fa9ed3…`.**
- [decimal-db-boundary-design.md](decimal-db-boundary-design.md) — design-only exact decimal ↔ database contract after the 0.12 scalar tier: canonical/display text, PostgreSQL `numeric` OID 1700 and typmod `((p<<16)|(s&0x7ff))+4` decoding, text-format binding and read-back (no binary/float), SQLite TEXT/INTEGER storage (REAL is rejected; NUMERIC/INTEGER affinity silently turns integer-valued decimals into INTEGER and loses display scale), `decimal::check` exact-fit rules (including negative scale), NULL-vs-zero with a temporary error-only API (no `?decimal`) pending `DecimalOrNull`, and composition with `sql` template binding via a lossless `DecimalText` payload. Design only; no version reserved.
- [decimal-text-api-design.md](decimal-text-api-design.md) — design-only P0 text surface for the approved decimal database boundary: strict public `decimal::parse` grammar (mandatory integer part, signed/integer-only DB cells, exact dscale, precision/display/exponent precedence), `decimal::format` fixed display text with `INEXACT` instead of rounding, `decimal::canonical` exact minimal/scientific text at the 128-byte fixed threshold, `decimal::check(value,p,s)` exact-fit metadata gate, and normalised `decimal::exponent` plus stored `decimal::dscale` for the PostgreSQL `-16383` pre-check; exact Result code/message tables, runtime slots 73–78, compiler builtins, tests/mutants, and the `DecimalText` composition. Revision 3 resolves the `a927acf` follow-up (explicit DB parse/check code-10 mappings, 32-byte err-block heap fixtures, parse-normalised-resistant mutant catchers, `main.obx` module coverage); baseline `2364add`; implementation follows field visibility (`0.13`/format 7), likely `0.14`/ABI 1; no version reserved. Decimal fields, `?decimal` and a SQL `Decimal` variant remain blocked.

- [native-c-interop-design.md](native-c-interop-design.md) — **REVISE response, explicit-close adapter checkpoint pending independent rereview** of the one-time generic in-process C interop (`__cinterop`): scalar ABI thunks, maintained ordinary obo wrapper modules, typed sidecar checks, system-toolchain non-PIE linking, conservative effects, provenance gates, a generation-checked C resource registry, and explicit-close libpq Connection/Rows adapters. - [interfaces-v3-design.md](interfaces-v3-design.md) — consolidated, implementable interfaces design (owning-first): `I` an owning box, `&I` borrowed with per-local pair slots, `^I` later; the "local" member effect tier with its summary rebuilt from `.sym` markers; parameter modes; `take`/`replace`; the lambda firewall fix (`containsIface` recurses into records); versions `0.8`/format 4/ABI 1 (lambdas shift to `0.9` and `0.10`, format 5); test and mutant inventory; design only, for review. - [interface-handles-design.md](interface-handles-design.md) — phase 2a design for `^I`, a checked handle to an owned interface box, on the released `0.11`/format 6/ABI 1 compiler and Stage B captures: the existing one-word `^T` token naming the box (no runtime/ABI change, but handle-materialization codegen fixes required), `handle` only on owned `I` places (through-handle places refused), `?^I`, liveness/`alive`, copy-only semantics and forbidden equality, dereference-before-arguments dispatch (S4), per-member effect rules with `pure mut` shared sinks, a narrow classifier-only direct-`^I` capture exemption (owned `I`/`&I` deferred), `.sym` compatibility, diagnostics, tests/mutants, and the separate 2b concrete-target pair. Design only, revision 2 for focused re-review; no version reserved.
- [template-literals-design.md](template-literals-design.md) — **approved design decisions 2026-10-31** (revision 3; baseline `c6c4d3f`): compiler-known built-in `sql`/`html` backtick tags over one **template-domain** abstraction, no general user-defined tag protocol in v1; SQL typed bind parameters versus `Sql` fragment composition; explicit `sqlJoin`/`sqlWhere` arrays; splicing consumes fragments and reuse requires `sql.copy`/`html.copy`; ordinary stdlib records with public fields and convention-level trust (not type-enforced); HTML text/quoted-attribute/URL escaping with claimed-safe `Html`/`HtmlAttrs` and rejected script/style/comment/name holes; no cross-domain `SafeString`; implement after Stage B `0.11`, no version reserved. Design only; implementation not authorized.
- [field-visibility-design.md](field-visibility-design.md) — **user decision: record fields are private by default, `pub` per field** (baseline released `34b798b`, `0.11`/format 6/ABI 1): module-level private fields; mixed records; opaque one-word `priv`/`priviface` slots in the `.sym` field list preserving layout without leaking field-list names/types, while exported `pf`/`pfree` summary paths may still name a private field (accepted v1 leak: a private-field change that affects such a summary changes the interface hash, while a field-list-only change may not); external `new T{...}` only when every field is `pub`, otherwise a module constructor; private field types may be private (closure check relaxed) with an interface-carrier bit and per-field clean visited set for the lambda firewall; closed-variant source fields stay public in v1 and migration never adds `pub` to them; methods/interfaces/borrows/moves/handles/C-token interactions, with `buffer::wrap` kept and the C registry as the security boundary; exact diagnostics including the foreign-only private-field-as-method message (public and same-module fields keep the existing field-not-method text); `.sym`/`--check`/hash rules, next-free version coordination with `^I` (no reservation), compiler anchors and the `2,500,000` budget; migration of 103 records, 71 real constructor sites (72 including one `html.obx:18` comment), 147 `pub type` lines, plus 28/22 embedded-Python definitions/sites, 3 regenerable goldens and 92 hand-written `.sym` fixtures; `fs::Dir` remains a public-field v1 exception and `io::Writer` gets `bufferedBytes`; decided private `Html.text` plus `raw` (revision of the template design's public-field sentence, including the `LANGUAGE.md` §8 HTML paragraph and `html.obx` comment). Design only; not implemented.
