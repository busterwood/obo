# Design notes

- [systems-stdlib-design.md](systems-stdlib-design.md) — design for review on released `51ce9e7` / obo 0.12: general-purpose Linux systems library core (identity, files, directories, metadata, mapping, clocks, random, streams/buffers, network/reactor, processes/signals), HTTP readiness assessment, and the process/reactor concurrency verdict. Core §3–4 and P0/P1a are the approvable slice; P2/P3 are directional; threads and synchronization are not in the core. Docs only, no version reserved.
- [http1-server-design.md](http1-server-design.md) — design for independent review (revision 4, reconciled with TLS `ea02b29`/in-progress `2c8a824`) on `2364add`: strict incremental HTTP/1.1 origin-server protocol layer above the approved systems stream/buffer/reactor contracts and an optional TLS `Transport` adapter. Covers start-line/header/chunk parsing, CL/TE smuggling defenses, framing and body streaming, response serialization and chunked writer, explicit step API and handler contract, owned TLS-compatible transport outcomes, absolute deadlines/backpressure/drain, security corpus, offline tests, TLS/HTML/SQL integration, phasing, rejected alternatives and open choices. No h2/h3, routing, TLS internals or compression; docs only, no version reserved.
- [http2-server-design.md](http2-server-design.md) — design for independent review on `db2146c` (TLS P2T-b, H1a0 and systems P2 merged): server-side HTTP/2 (RFC 9113) above the approved TLS/stream/buffer/reactor contracts, binding the system nghttp2 1.59.0 through a trusted C shim with scalar tokens, bounded fixed-event/header/body queues, a complete-frame wire ring, a deferred data provider, no pointers and no callbacks into obo. Defines `KIND_H2_CONNECTION`/`KIND_H2_STREAM`, adopt/orphan/close lifetime, per-stream events and windows, SETTINGS/preface/GOAWAY drain, HEADERS/CONTINUATION/DATA/trailers/reset/padding/priority policy, rapid-reset/CONTINUATION/HPACK/header-list caps, deadlines, a shared `httpapi` request/action vocabulary with a pure `Action` handler and concrete `httptransport` (no impure interface), h2spec/h2load/curl/Go/fuzz/ASAN gates, phasing, rejected alternatives and open choices. TLS ALPN `h2` first, opt-in h2c prior knowledge, no push/client/HTTP3; nghttp2 headers required with a pinned `libnghttp2-dev` provenance note. Docs only, no version reserved.
- [http3-server-design.md](http3-server-design.md) — revision 3 design for short re-check on `544dff8` (HTTP/2 H2b/H2c, TLS P2T-b and H1c merged): native server-side HTTP/3 (RFC 9114) over QUIC v1 (RFC 9000) above the existing HTTP/1.1/2 server, systems and TLS layers. Chooses system ngtcp2 0.12.1 + nghttp3 0.8.0 with GnuTLS 3.8.3 through `libngtcp2_crypto_gnutls`, not OpenSSL 3.0 (no QUIC API) and not the TCP `systls` adapter; a separate internal `quictls` C unit; a `sysnet` UDP batch/GSO/GRO prerequisite; a trusted C shim with scalar tokens, fixed event/wire batches, CID routing, Retry/stateless-reset/version-negotiation policy and no pointers or callbacks into obo; QUIC v1 handshake/transport parameters, ALPN `h3`, control/QPACK streams, SETTINGS, request/response headers, DATA, trailers, GOAWAY, bounded stream/QPACK/header caps, 32 concurrent requests and 1 MiB connection window; 0-RTT, push, WebTransport, HTTP/3 datagrams, client mode and active migration disabled; `disable_active_migration=1` with validated NAT rebinding; one authority per connection and 421 otherwise; concrete `quic::Server`/`Connection`/`Stream` shells, `http3` request/response API, shared `httpapi` `RequestMeta`/`Action`/`Handler` seam, deadlines, flow control, graceful drain; hermetic in-tree test client plus conditional h3spec/aioquic/gtlsclient/curl-built integration, loss/Retry/0-RTT/migration/malformed/ASAN gates; phasing H3a/H3b/H3c plus a sidecar fallback; rejected alternatives and open choices. Docs only, no version reserved; sidecar is a deployment bridge, not native HTTP/3.
- [systems-threads-design.md](systems-threads-design.md) — separate P4/P5 design for confined native threads and synchronization on obo 0.12: T2 context-relative globals/identity table as a prerequisite, T1 only as a compute/native restriction, worker-entry ABI without C-to-obo callbacks, hosted TLS/pthread qualification, per-worker arenas, reclamation by joinable supervisor, and P5 byte channels plus AtomicInt/AtomicBool only. SharedBytes/Mutex/Condvar/RwLock/Once and Send/Sync markers are explicitly deferred. Docs only, no version reserved; P4/P5 blocked on T2.
- [tls-adapter-design.md](tls-adapter-design.md) — revision 3 design for focused re-review on `main` `2364add`: server-side TLS 1.2/1.3 over `sysstream`/`sysreactor` for HTTP/1.1 and HTTP/2. Chooses system OpenSSL 3.0 `libssl.so.3`/`libcrypto.so.3` with required headers (declarations-only rejected for OpenSSL macros), memory BIOs instead of `SSL_set_fd`, C-only ClientHello/ALPN/SNI/info callbacks, and no pointers/structs/callbacks into obo. Defines non-optional owned `TlsContext`/`TlsSession` shells over `platform::Resource` (target `pub res` + private `transport`), explicit close and leak counters, ALPN default `http/1.1` with `h2` only after HTTP/2, ClientHello-based ALPN `Require`, output-first SSL handling (`WantWrite` when wbio/C staging is non-empty), explicit `flush`/`flushPending`, multi-step shutdown, outcomes carrying `want`, single TLS error family, peer verification, no tickets/0-RTT, nonblocking WANT/close_notify/truncation state tables, the OpenSSL trust/provenance boundary, a full local test matrix, and P2T phasing after syslib P2 approval/implementation. §11.3 aligns with the HTTP/1.1 `Transport` at `3207148` (no `source()`/`shutdownWrite`, no WouldBlock mapping). No HTTP parsing, no QUIC/DTLS, client mode separate, hosted-only. P2T-b implementation is experimental under `../experimental/tls/`; §17 records it and it remains pending independent review. No version reserved.
- [decimal-research-2026-10-28.md](decimal-research-2026-10-28.md) — database-first research for a lossless decimal type (SQL Server, Oracle, Sybase, PostgreSQL storage formats; 38-digit/24-byte recommendation). Historical research: decimal is released at `0.12`.
- [decimal-language-design.md](decimal-language-design.md) — approved design for language integration of the 24-byte `decimal`, baseline `4a072cf`, after Stage B `0.11`; final literal/type/arithmetic/conversion decisions (bare fractional literals, trap-on-overflow `+ - *`, compile-error `/`, explicit `div` returning `Result`, explicit conversions, display-scale preservation with a DB-style cap, exit-10 trap codes), 24-byte ABI, containers, formatting, database boundary `check`, phased plan and open engineering choices. **Approved 2026-10-31; the minimum scalar tier is released as `0.12`/format 6/ABI 1, merged and promoted on main after rebasing on 0.11 HTML main `34b798b`. The promoted `seed/obo` is the same 0.12 image (643,073 bytes, `d98d6b5f…`), built once by the 0.11 seed `01fa9ed3…`.** D4a (decimal methods and interface members) is released as `0.18`/format 11/ABI 1; D4b (decimal function values, lambda parameters/returns and captures) is implemented as `0.19`/format 12/ABI 1 on `decimal-d4b`, seed not promoted.
- [decimal-storage-plan.md](decimal-storage-plan.md) — staged plan for the decimal storage and usability tier: D1 record/variant fields, D2 `[]decimal`, D3 globals/constants and D4a methods/interface members, plus D4b function values/lambdas/captures, D5 the library-only `lib/decimals.obx` and D6 the database read bridge. D1–D3 are released as `0.16`/format 9/ABI 1 (seed `50cca0a`); D4a is implemented and released as **`0.18`/format 11/ABI 1** (merge `e47a8c8`, seed `769a359`); D4b is implemented as **`0.19`/format 12/ABI 1** on `decimal-d4b` (seed not promoted), then D6. D5 is released on the 0.17 line as a library-only addition.
- [decimal-d4b-layout.md](decimal-d4b-layout.md) — **implemented on `decimal-d4b` (0.19/format 12/ABI 1); layout revision 2 approved with nits, seed not promoted.** D4b frame layout for decimal function values and lambdas: the value-call cell is pushed above the hidden decimal destination so the callee keeps reading it at `16 + visibleTypeParamsBytes(params)` (direct, method and interface calls unchanged), the lambda environment pseudo-parameter is removed from both `hp` and `FnRec.params` and the read becomes a byte offset (`16 + A`, or `24 + A` for a decimal return), Stage B decimal captures are 24-byte value snapshots at byte offsets, and the `.sym` decision is format 12 / `0.19` with `SYM_ABI` 1. Includes refusals, effects, tests/mutants, the by-address equivalent record and the stepwise implementation order.
- [decimal-db-boundary-design.md](decimal-db-boundary-design.md) — design-only exact decimal ↔ database contract after the 0.12 scalar tier: canonical/display text, PostgreSQL `numeric` OID 1700 and typmod `((p<<16)|(s&0x7ff))+4` decoding, text-format binding and read-back (no binary/float), SQLite TEXT/INTEGER storage (REAL is rejected; NUMERIC/INTEGER affinity silently turns integer-valued decimals into INTEGER and loses display scale), `decimal::check` exact-fit rules (including negative scale), NULL-vs-zero with a temporary error-only API (no `?decimal`) pending `DecimalOrNull`, and composition with `sql` template binding via a lossless `DecimalText` payload. Design only; no version reserved.
- [decimal-text-api-design.md](decimal-text-api-design.md) — design-only P0 text surface for the approved decimal database boundary: strict public `decimal::parse` grammar (mandatory integer part, signed/integer-only DB cells, exact dscale, precision/display/exponent precedence), `decimal::format` fixed display text with `INEXACT` instead of rounding, `decimal::canonical` exact minimal/scientific text at the 128-byte fixed threshold, `decimal::check(value,p,s)` exact-fit metadata gate, and normalised `decimal::exponent` plus stored `decimal::dscale` for the PostgreSQL `-16383` pre-check; exact Result code/message tables, runtime slots 73–78, compiler builtins, tests/mutants, and the `DecimalText` composition. Revision 3 resolves the `a927acf` follow-up (explicit DB parse/check code-10 mappings, 32-byte err-block heap fixtures, parse-normalised-resistant mutant catchers, `main.obx` module coverage); baseline `2364add`; implemented and released as `0.14`/format 7/ABI 1. Decimal fields, `?decimal` and a SQL `Decimal` variant remain blocked.

- [impure-interface-members.md](impure-interface-members.md) — **implemented and released as `0.17`/format 10/ABI 1** (stage I1, compiler only; merged as `06a0fe1`, seed `e0b9686`). Adds the third interface-member tier: `impure fn`/`impure mut fn`, a synthetic maximum summary (`freesAll`, `writesHandles`, no named frees) rebuilt identically by the source parser and the `.sym` reader, full reference/handle invalidation at every call, any signature-matching method as implementation (the declaration is an upper bound), unchanged pure/plain tiers, no vtable or code-generation change, and the canonical `.sym` marker with format 9→10 (`SYM_ABI` stays 1). Stage I2, the `http1server` handler interface with a data-carrying response and the handler in a local or `&I` parameter, is the follow-up; async libpq and a deferred response come after that.
- [template-literals-design.md](template-literals-design.md) — **approved design decisions 2026-10-31** (revision 3; baseline `c6c4d3f`): compiler-known built-in `sql`/`html` backtick tags over one **template-domain** abstraction, no general user-defined tag protocol in v1; SQL typed bind parameters versus `Sql` fragment composition; explicit `sqlJoin`/`sqlWhere` arrays; splicing consumes fragments and reuse requires `sql.copy`/`html.copy`; ordinary stdlib records with convention-level trust (not type-enforced), with `Sql`/`SqlArg` public and `Html.text` private to module `html` (revision 4); HTML text/quoted-attribute/URL escaping with claimed-safe `Html`/`HtmlAttrs` and rejected script/style/comment/name/unquoted/srcdoc/style/`on*` holes; URL values are validated as assembled attribute values and a scheme may not span holes; `sqlWhere` parenthesizes every predicate and `sqlJoin` holds its parts across the separator; no cross-domain `SafeString`. Implemented and released as `0.15`/format 8/ABI 1; `seed/obo` is the matching 0.15 image. SQL driver binding, identifier/`ORDER BY` allow-lists and dialect `$n` rendering remain later work; `DecimalText` is the lossless decimal transport.
- [field-visibility-design.md](field-visibility-design.md) — **user decision: record fields are private by default, `pub` per field** (baseline released `34b798b`, `0.11`/format 6/ABI 1): module-level private fields; mixed records; opaque one-word `priv`/`priviface` slots in the `.sym` field list preserving layout without leaking field-list names/types, while exported `pf`/`pfree` summary paths may still name a private field (accepted v1 leak: a private-field change that affects such a summary changes the interface hash, while a field-list-only change may not); external `new T{...}` only when every field is `pub`, otherwise a module constructor; private field types may be private (closure check relaxed) with an interface-carrier bit and per-field clean visited set for the lambda firewall; closed-variant source fields stay public in v1 and migration never adds `pub` to them; methods/interfaces/borrows/moves/handles/C-token interactions, with `buffer::wrap` kept and the C registry as the security boundary; exact diagnostics including the foreign-only private-field-as-method message (public and same-module fields keep the existing field-not-method text); `.sym`/`--check`/hash rules, next-free version coordination with `^I` (no reservation), compiler anchors and the `2,500,000` budget; migration of 103 records, 71 real constructor sites (72 including one `html.obx:18` comment), 147 `pub type` lines, plus 28/22 embedded-Python definitions/sites, 3 regenerable goldens and 92 hand-written `.sym` fixtures; `fs::Dir` remains a public-field v1 exception and `io::Writer` gets `bufferedBytes`; decided private `Html.text` plus `raw` (revision of the template design's public-field sentence, including the `LANGUAGE.md` §8 HTML paragraph and `html.obx` comment). Implemented as `0.13`/format 7/ABI 1, merged and promoted on main; `seed/obo` is the matching 0.13 image.
