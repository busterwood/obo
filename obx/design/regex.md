# A regex engine for obx

Status: plan, 2026-11-03, agreed. R1 has started. No language change is
needed.

## 0. Goal and choice

`import "regex"` gives regular expressions that are safe on any input:
matching time is linear in the input's length, whatever the pattern. This
is the RE2 family, which Go's `regexp` and Rust's `regex` both belong to:
no backreferences and no lookaround, which are the features that make
backtracking engines exponential.

The design is Go's, ported: a parser, a compiler to a small instruction
program, and three matchers chosen per pattern and input. On top of it come
Rust's two biggest wins, a literal prefilter and a lazy DFA (R2). Rust's
whole engine (about 50,000 lines with its SIMD and special cases) is too big
to port faithfully. Go's (about 6,000) can be ported and checked line by
line against its tests.

Needed for the tools on the roadmap: fd matches filenames with a regex by
default, and jq has `test`, `match` and `sub`. jq's own engine
(Oniguruma) has backreferences and lookaround, so jq programs that use them
will not run.

Licences: Go is BSD-3-Clause and Rust's regex is MIT or Apache-2.0, both
compatible with obx's Apache-2.0. Ported code keeps a header naming its
origin, and `NOTICE` carries their copyright lines.

## 1. Syntax

RE2's syntax, as in Go:
- literals and escapes;
- `.`, `[...]`, `[^...]` and `[[:alpha:]]`;
- `\d \w \s` and their negations;
- `\pL \pN` (R1), and `\p{Greek}` and the other scripts (R3);
- `* + ? {n,m}` and their lazy forms;
- `|`, `(...)`, `(?:...)` and `(?P<name>...)` / `(?<name>...)`;
- flags `(?i)`, `(?m)`, `(?s)` and `(?U)`;
- `^ $ \A \z \b \B`.

Patterns and text are UTF-8 strings, matched by code point. An invalid
UTF-8 byte in the text matches only `.` and negated classes, as in Go.

Refused with a clear error: backreferences (`\1`), lookaround (`(?=`,
`(?!`, `(?<=`, `(?<!`), possessive quantifiers, a repetition count above
1000, and a program larger than a fixed limit (as in Go, so a pattern
cannot exhaust memory).

## 2. API

```obx
import "regex"

let re = try regex.compile("(?P<y>\\d{4})-(?P<m>\\d{2})-(?P<d>\\d{2})")
if re.isMatch("on 2026-11-03") { ... }
match re.find(text) { Some(m) { m.start; m.end; m.text } None {} }
for m in re.findAll(text) { ... }
match re.captures(text) {
    Some(c) { let y = c.name("y").unwrap().text }
    None {}
}
let s = re.replaceAll(text, "$d/$m/$y")
let parts = re.split(text)
```

- `compile` returns `Result[Regex, regex.Error]`. The error carries the
  position and the reason. `regex.mustCompile` is for constants.
- `Regex` is immutable once compiled, and a copy handle shares the program.
  The matching state (thread lists, the backtracker's bitmap, later the DFA
  cache) is per call or kept in a small per-`Regex` cache. With tasks on
  one thread nothing is shared across threads, so no locks are needed.
- Offsets are byte offsets into the string, as in Go and Rust.
- `regex.quote(s)` escapes a literal.

## 3. Phases

### R1: Go's engine

| Part | Go source | Notes |
|---|---|---|
| parser and syntax tree | `regexp/syntax/parse.go` | the flags, classes, names and limits in section 1 |
| simplification | `simplify.go` | `x{2,5}` expanded, and so on |
| compiler to a program | `compile.go`, `prog.go` | the instructions: rune, rune ranges, any, empty-width assertions, split, capture, match |
| backtracker | `backtrack.go` | for small programs times small inputs, with a visited bitmap, so still linear |
| one-pass matcher | `onepass.go` | for patterns where every step has one choice: captures in one pass |
| Pike VM | `exec.go` | the general case: an NFA simulation with captures |
| API | `regexp.go` | `find`, `findAll`, `captures`, `replace`, `split` and their index forms |

Unicode in R1: `\pL`, `\pN`, `\pZ` and the other general categories, with
simple case folding for `(?i)`. The tables are generated by a Python script
from the Unicode data file that Go's tables come from. Scripts and full
case folding are R3.

Tests:
- Go's test tables ported as obx tests: `find_test.go`, `all_test.go`, the
  `re2-search.txt` exhaustive cases, and the parse and error tests. Every
  expected result is compared with Go's.
- A random generator, as `vrgen.py` is for the compiler: patterns and
  texts, with the results compared against Go's `regexp`, which is
  installed here, by a small Go driver program.
- Hostile patterns stay linear: `(a*)*b` and `(x+x+)+y` over long inputs,
  with the time bounded.

Gate:
- Go's tests pass and the generator finds no difference;
- no leaks under `OBX_CHECK=1`, ASan and UBSan, on both backends;
- speed within a small factor of Go's `regexp` on the benchmark set
  (section 4), natively.

### R2: Rust's wins

- **Literal prefilter.** From the syntax tree, find the literal prefix, or
  the literals one of which every match must contain. The search then
  jumps to them with a fast memory search: `memchr`, or a word-at-a-time
  `memmem`, in the runtime; Aho-Corasick for a few literals. For most real
  patterns this is where ripgrep's speed comes from.
- **Lazy DFA** (RE2's and Rust's "hybrid"): DFA states are built from the
  program while matching, in a cache of fixed size. A search runs forward
  to find where the match ends, then backward with the reversed program to
  find where it starts. Only when captures are asked for does the Pike VM
  (or the one-pass matcher) run on that span. If the cache fills too often,
  the search falls back to the Pike VM.

Gate: within a small factor of Rust's `regex` on the benchmark set, and the
tests and the generator still agree with Go.

### R3: Unicode, and what tools need

- `\p{Script}` with scripts and blocks, and full case folding for `(?i)`,
  from generated tables.
- A `RegexSet` that matches several patterns in one pass (fd's
  `--exclude`, routing).
- A byte-oriented mode for matching non-UTF-8 bytes (file contents, as in
  ripgrep).

## 4. Benchmark set

`obx/bench/regex/`: a few MB of text (English prose, a source tree's
files, a log file) and these patterns:

| Kind | Example |
|---|---|
| a literal | `Sherlock Holmes` |
| literals in an alternation | `Sherlock\|Holmes\|Watson\|Irene` |
| a class repeated | `\w+` (all matches) |
| case-insensitive | `(?i)sherlock` |
| something like an email | `[a-z0-9._%+-]+@[a-z0-9.-]+\.[a-z]{2,}` |
| anchored lines | `(?m)^ERROR .*timeout$` |
| captures | the date pattern in section 2, every match with its groups |
| a hostile pattern | `(a*)*b` over 100,000 `a`s |

Each pattern is timed against Go's `regexp` and Rust's `regex`, through
small driver programs built here, and against ripgrep as a reference
point. The results go in `PERFORMANCE.md`.
