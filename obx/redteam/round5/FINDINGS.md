# Red-team findings, round 5 (2026-11-02)

Reviewed: the language changes on branch `lang` (main..lang): multi-variant
match arms, `s[i]` on `str`, built-in `==`/`!=` on fieldless closed types, raw
strings, `nullPtr()`, `var` receivers, Option/Result `map`/`mapErr`/
`unwrapErr`/`expectErr`, a shared borrow of a constant as a temporary copy,
`return`/`break`/`continue` as a whole arm of an if or match expression (SPEC
7.8), a variable moved on some paths and dropped on the others (SPEC 9.1), C
callbacks, C varargs, scalar arrays and slices passed to C, and `lib/ffi.obx`.

    python3 obx/redteam/round5/rt.py              # cases/ and gen/
    python3 obx/redteam/round5/rt.py --no-native  # C backend only
    python3 obx/redteam/round5/gen.py DIR [count] [seed]

`rt.py` builds each program with the C backend under ASan+UBSan and runs it
with `OBX_CHECK=1` (leaks exit 5), then builds it with `--native` and runs it
again; both must match the directives (`// expect:`, `// exit:`, `// error:`).
A generated program (`// expect-any`) has no reference output: the oracle is a
clean sanitizer run and the native build printing exactly what the C build
prints.

Corpus: 374 programs, all passing after the fixes.

- `cases/`, 174 hand-written (60 expect a compile error): `e9_` exit arms
  (39), `m10_` moves on some paths (48), `p01*` compound assignment (8),
  `c11_` callbacks (13), `v12_` varargs (8), `a13_` arrays to C (11), `k8_`
  borrowed constants (8), `k6_` var receivers (5), `k3_` closed-type `==` (8),
  `k2_` `s[i]` (9), `r4_` raw strings (9), `o7_` Option/Result (4), `f14_` ffi
  (4).
- `gen/`, 200 generated by `gen.py` (seed 5): one function `f(k)` nesting if
  and match expressions with exit arms inside calls, record, variant and array
  literals, receivers and sums; consumed match scrutinees with owned bindings;
  moves of owned locals on some paths; if statements, for and while loops.
  Every owned value prints when made, taken and dropped. A further 1,800
  generated programs (seeds 1 and 2) were run and not committed: all clean.

Counts: 2 high (use after free), 1 low (lost output). No finding in the exit
arms or the partial moves themselves.

## High

- **F1** `p01_compound_rhs_moves_root` (predates `lang`; also on main):
  `x.v += take(x)` was accepted. A compound assignment evaluates the place,
  then the right side, then stores; the store did not check that the right
  side had moved the place's variable, so it wrote into the record `take` had
  freed (ASan: heap use after free). Also `xs[0] += take(xs)`, `x.a.v +=
  take(x)`, `x.ys[0] += take(x)`, `x.s += name(x)`, and with the SPEC 9.1
  rule `x.v += if c { take(x) } else { 5 }` (moved after the join).
  Fix (3186f51): `sAssign` rejects the store when the place's root variable
  is moved after the right side ("'x' was moved and has no value here"), as
  plain assignment already did. A right side that only borrows the root, or
  exits (`x.v += if c { return x.v } else { take(y) }`), is still allowed.
  Tests: `tests/error/rt5_p01*`.
- **F2** `c11_global_str_reassigned_in_callback`: a global `str` passed to an
  extern `str` parameter was passed by its bytes (`rt_cstr` passes a str that
  is already NUL-terminated without copying, such as the result of a
  concatenation), not held by the call. A callback that assigns the global
  (`K = ...` inside the `bsearch` comparator) freed the bytes C was still
  reading: ASan use after free; without ASan `bsearch` returned the wrong
  answer. Also a `str` field of a global value record
  (`c11_global_field_str_reassigned`). Fix (3186f51): in `call()` for an
  extern with a `str` argument, a `str` read from a global is copied into a
  temporary held until the end of the statement. SPEC 12 says so now.
  Test: `tests/run/rt5_c11_global_str_extern_arg`.

## Low

- **F3** `c11_atexit`: output printed by a callback that C calls as the
  program ends (`on_exit`/`atexit`, after main returned, after `exit`, after a
  panic) was lost: the runtime flushes its buffer before C's exit handlers run
  and nothing flushes it again. Fix (3186f51): both runtimes (`rt.h`,
  `native/rt.c`) set `rt_ended` when the program ends (main's end, `exit`, a
  trap, a panic; the native `rt_quit`), after which stdout writes go straight
  to the file. SPEC 12 says so now. Tests: `c11_atexit*`,
  `tests/run/rt5_c11b_output_at_exit`.

## Spec changes

No rule was tightened. Two clarifications in SPEC 12 for F2 and F3: a callback
may assign a global whose `str` the extern call was passed (the call holds the
value), and output after the end of `main` (from a callback at exit) is written
at once. F1 is the existing rule of SPEC 7.3 ("the value is stored to the place
after `b` has run", as in `a = a + b`) applied to moves.

## What held up

- Exit arms (SPEC 7.8): temporaries made before the exit arm dropped exactly
  once (frames, nested calls, `&&` operands, record, variant, array and
  generic record literals, receivers moved at the call, destructuring lets,
  index and slice bounds, consumed match scrutinees and for-loop temporaries
  with `break`), in loops (`continue` after a move, `while` conditions),
  closures, generic functions, types with `drop` methods, placeholder arms of
  match expressions, implicit moves at the call. An expression whose every
  arm exits is rejected ("has no value").
- Moves on some paths (SPEC 9.1): drops at the join, before later effects of
  the statement; snapshots of operands left of an expression that moves
  (`x.s + if c { take(x) } ...`); borrows, receivers, slices, indexes and
  `len` left of a move are rejected; moves in loops are rejected across
  iterations; closures; match arms with owned bindings; drop order.
- Callbacks: narrow integer parameters (C and native agree), re-entrant
  `qsort`, function values in variables, fields and generic instances,
  closures and method values rejected.
- Varargs: default promotions, borrows, substring temporaries, exit arms in
  varargs. Arrays to C: a late borrow sees the grown buffer, trap order, empty
  arrays and slices, constant tables.
- Built-in `==` on closed types (with and without an `eq` method, constants,
  one-variant types), `s[i]` and slices of a global `str` whose index assigns
  the global (the old value is read), raw strings, `nullPtr()`, `var`
  receivers, Option/Result methods, borrowed constants, `lib/ffi.obx`.

Conservative but consistent, not filed: `pair(x, if c { return x } else {..})`
is rejected ("overlaps a borrow held by the call") while `pk(&x, if c {
return x } else { 1 })` is allowed (the borrow is taken at the call, after the
exit arm).
